# 雙核心配置與公平比較

比較兩個相同工作都固定於 Core 1，和分別固定於 Core 1／Core 0 的差異。這裡的「同核心」是工作配置，並沒有把整個 ESP32 改為單核心模式。

## 操作與判讀

OLED 接一般模式 SDA 21／SCL 22。程式自動交替執行兩組測試，結果保留 8 秒：

| 畫面 | 兩個工作的位置 |
|---|---|
| `RUN CPU1 + CPU1`／`SAME CORE DONE` | 兩個 Task 都固定 Core 1 |
| `RUN CPU1 + CPU0`／`DUAL DONE` | 分別固定 Core 1、Core 0 |

兩個工作以 Event Group 等候共同起跑訊號，執行相同整數迴圈，回傳實際核心與 checksum。每 50000 次運算讓出至少一個 tick，總共 200 批，避免長時間霸占 CPU。這個刻意讓出的等待時間也算在耗時內。

`ELAPSED` 是兩個結果都回到主程式前的總牆鐘時間；包含排程、等待、Queue 與 UI 輪詢開銷。`CHECK OK` 表示兩個工作計算結果一致，不是相機或感測器驗證。受這些開銷與系統服務影響，雙核心不保證快兩倍，甚至可能沒有明顯改善。

## 程式設計

`xTaskCreatePinnedToCore()` 最後一個參數是核心編號；優先序 1、堆疊 3072 bytes。工作完成前透過 Queue 傳回 Result，最後自我刪除。Task 引數放在生命週期足夠長的全域 `jobs`，不把已離開函式的區域變數位址交給背景工作。

建立工作失敗時，起跑閘門仍關閉，程式可刪除尚未持有資源的另一工作；執行中不強行刪除其他核心正在持有資源的工作。超過 30 秒顯示 `TIMEOUT` 並停止安排新測試；查明原因後重啟。

## 驗收表

記錄至少 5 組同核心／雙核心耗時、實際核心與 checksum；重啟後再觀察一次。結果表保持空白直到真實執行，不把 CI 編譯時間填成板上測試數字。

| 次數 | 同核心 ms | 雙核心 ms | CPU 回報 | Checksum |
|---|---|---|---|---|
| 1～5 | 待實測 | 待實測 | 待實測 | 待實測 |

練習：改變每批運算量，保持兩組相同，再比較等待比例對結果的影響。不能從這個小程式推論所有相機或網路程式都適合固定核心。
